A five-minute tour

  1. Model. Open the Studio on office-01. Switch between the Diagram and Table views. The breadcrumb leads up to the domain model and the metamodel. The badge "10 of 10 sensors online" is the fleet's heartbeat, simulated here.
  2. Commit. In the Table view, change the label of an access point and press Save. The model moves to version 2. Changes stay in this browser; "Reset demo" restores the captured model.
  3. Gate. Remove the sensor acs1_co2 from acs1 → senses. The check reports C8.TOO_FEW and P5.INPUT_UNBOUND (the KPI co2.avg would read an unbound sensor), and Save is disabled. Press Discard.
  4. Fleet. Open the fleet. The Map shows the projection the fleet pulled and the bundle each device received. The PIP tab lists the 18 recorded decisions, and new ones arrive as the run is replayed.
  5. Twin. Open ACS-1. Put EVAL-TAG-4 in the tag field and press TAG_DETECTED: the twin goes to s_denied with reason revoked. EVAL-TAG-1 is allowed; EVAL-TAG-2 is unknown_credential on ACS-1 but allowed on ACS-2.

What is live and what is recorded

Studio: model, conformance, commit gate, projection, exportLive. The metamodel library runs in the page, starting from the rows captured in the Studio's database.
Fleet and twins: all readsRecorded from the running system (simulated devices) right after the 18 probe taps of the evaluation.
Fleet and twin event streamsReplayed in a loop, with their original timing. Timestamps are shifted to the present.

Configuration changes in fleet and twins (rules, KPIs, statecharts)Not applied; a notice says so. Override and inherit on a twin are kept in memory.
